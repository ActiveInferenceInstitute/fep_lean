This slice opens the operations stage of the [GNN bridge
program](../../docs/design/gnn-bridge/README.md) under the [bridge
contract](../../docs/design/gnn-bridge/bridge-contract.md). It adds one
read-only health command for the bridge — `bridge_status.py` — that
exercises the Direction 1 pipeline end to end (emitter freshness,
certificate protocol, syntax-surface pin, formal projection drift) and
exits 0 iff every check passes. Spec-first: this file precedes any code.

## Why

Directions 1 and 2 each have accepted slices with per-slice gates, but no
single command answers "is the bridge healthy right now?". Operators
currently run the P1 `--check`, the P3 `certify.py`, and the projection
`--check` gates separately and by memory. W1 composes the existing
accepted-slice tooling into one status surface without modifying any of
it (the accepted slices' scripts are imported or invoked, never edited).

## The four checks

`specs/gnn-bridge-w1-bridge-operations/bridge_status.py` (structure and
copy conventions follow `specs/gnn-bridge-p3-certificates/certify.py`)
reports each check PASS/FAIL with one evidence line; overall exit 0 iff
all pass.

1. **Freshness** — loads the P1 emitter via `importlib` from
   `specs/gnn-bridge-p1-finite-spike/projection.py` and calls its
   `build_document(heads)` with `git rev-parse HEAD` from both repos
   (same inputs the emitter uses). Regenerated bytes are compared against
   the on-disk `specs/gnn-bridge-p1-finite-spike/gnn-input/FepLeanSymmetricBool.md`.
   On mismatch the failure is classified:
   - every differing line is a provenance digest line
     (`source_commit` / `pipeline_commit`) → `STALE-CUSTODY
     (digest-only)`;
   - otherwise → `CONTENT-DRIFT`.
   Both classifications FAIL the gate; only the operator remediation
   differs (`--refresh-digests` heals custody drift; content drift needs
   re-emission review). The accepted slice's script is imported, never
   edited.
2. **Certificates** — re-invokes
   `uv run python specs/gnn-bridge-p3-certificates/certify.py` via
   subprocess against its default artifacts. PASS iff exit 0 (C1/C2
   within tolerance). Its regeneration of `certificates.json` /
   `CERTIFICATES.md` is byte-identical when green — accepted custody
   behavior of the P3 slice, not re-verified here.
3. **Syntax-surface pin** — reads
   `specs/gnn-bridge-w1-bridge-operations/syntax-pin.json`, which records
   the sha256 of GNN `doc/gnn/gnn_syntax.md` and GNN
   `src/pipeline/step_registry.py` at the Q1 pin, plus the GNN commit
   digest. The digests are recomputed against the sibling GNN checkout
   (`../GeneralizedNotationNotation` relative to the fep_lean root).
   Drift → FAIL with the bridge-contract §9 re-freeze instruction (open
   a re-pin slice; never silently accept a moved surface). Missing pin
   file → FAIL with creation instructions.
4. **Formal projection drift** — subprocess
   `uv run python scripts/_maint_build_formal_modules.py --check`
   (the manifest-driven canonical→mirror projection gate). PASS iff
   exit 0.

## Refresh mode

`--refresh-digests` rewrites the P1 document via the emitter's
`build_document(current heads)` — it heals custody drift only and never
touches content-bearing lines. Default run is read-only.

## CLI surface

The script prints a summary table at the end, mirroring the
`fep-lean atlas --check` reporting style: one row per check
(name, result, evidence), then the overall verdict and exit code.

## Boundaries

- No edits to any already-accepted slice's scripts; the P1 emitter is
  imported, the P3 certifier subprocessed, the projection gate
  subprocessed.
- The syntax pin file is created in this slice from the GNN checkout's
  current HEAD surface (both pinned files verified clean against HEAD at
  pin time — a working-tree pin note would be recorded otherwise).
- fep_lean-side only; no GNN repo writes.
- Cross-repo references are inline code paths, never markdown links.
